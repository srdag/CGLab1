# 🌋 Vulkan Starter App

## С чего начать

Перед сборкой проекта необходимо установить компилятор C++, Vulkan SDK и CMake.

Проект использует стандарт C++20, поэтому нужен один из следующих компиляторов:
- GCC 10.X
- Clang 10
- Microsoft Visual Studio 2019

Официально проект протестирован на *Windows* и *GNU/Linux*, поддержки *macOS* пока нет.
Если у вас есть рабочее решение этого кода для macOS, предложите PR, чтобы другие
тоже могли собрать этот пример без лишних хлопот!

<ins>**1. Загрузка репозитория**</ins>

Для начала клонируйте репозиторий командой `git clone --depth 1 https://github.com/vladeemerr/vulkan-starter-app`

Репозиторий не содержит сабмодулей — вместо них используется механизм `FetchContent` из CMake.

<ins>**2. Конфигурация проекта**</ins>

Выполните одну из команд CMake, чтобы скачать зависимости и сконфигурировать проект:

```bash
cmake --preset debug      # для GNU/Linux (GCC/Clang)
cmake --preset msvc-debug # для Windows (Visual Studio 2019)
```

Если хотите собрать проект в режиме `release`, замените `debug` на `release`.

Если в проекте что-то изменилось (добавлены или удалены файлы) или нужно заново сгенерировать файлы проекта, повторно выполните команду выше.

<ins>**3. Сборка**</ins>

Для сборки проекта используйте команду ниже. Скорее всего, вы используете пресет `debug`, поэтому
каталог, в котором в итоге окажутся файлы сборки, будет называться `build-debug`.

Аналогично для `release` этот каталог будет называться `build-release`.

Выполните одну из этих команд в зависимости от выбранного пресета:

```bash
cmake --build build-debug --parallel # для debug
cmake --build build-release --parallel # для release
```

### Запуск

После успешной сборки исполняемый файл окажется в одном из подкаталогов каталога `build-*`.

Для сборок `msvc-{debug|release}` подкаталог вывода — `Debug` или `Release` соответственно.
Для остальных конфигураций подкаталог вывода — `vulkan-starter-app`.

**Убедитесь, что рабочий каталог (working directory) установлен в корень проекта!**
Корень проекта — это каталог, где лежит этот README. Иначе код,
отвечающий за загрузку шейдеров и других ресурсов из файлов, не сработает,
потому что используются относительные пути.

### Компиляция шейдеров

В `CMakeLists.txt` есть правило сборки, которое компилирует файлы шейдеров
вместе с приложением. Найдите в этом файле комментарий — там
описано, как компилировать ваши шейдеры.
